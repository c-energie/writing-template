# AGENTS.md

Instructions for any coding agent working in this repository — Claude Code, Cursor,
GitHub Copilot, Codex, Windsurf, Aider, Zed, Gemini, or a chat assistant a human is
pasting files into. This file is the portable, tool-neutral contract; `.claude/` holds
Claude-specific extras that mirror it.

## What this repository is

A long LaTeX document — thesis, report, or book. **The prose is the only thing written by
hand here.** Figures and tables are generated by a companion Python repository and land
here as artefacts. A publishing engine can flatten the result into a corpus, a wiki, or a
website.

```
analysis-template ──figures/tables──> THIS REPO ──ingest──> doc-publish
                                          │
                                          └──> Overleaf ──> the PDF
```

This repository contains **no Python and no build system beyond a Makefile.** Do not add
either. The two companion repositories locate this one through the `DOC_REPO` environment
variable; nothing here imports their code and nothing here should.

## Rules that matter

These fail *silently* if broken, which is why they are stated rather than left to be
inferred.

1. **Never rename a committed figure.** LaTeX resolves bare filenames via `\graphicspath`
   and the publishing manifest indexes by name. A rename breaks both with no error, and
   two files sharing a stem report as `ambiguous`.

2. **Figures are referenced by bare filename**, never by path:
   `\includegraphics{example_scatter.png}`. `\graphicspath` in the `.sty` resolves it.
   **It does not recurse** — every directory holding figures needs its own line there.

3. **Labels mirror filenames.** `example_scatter.png` ↔ `\label{Fig: example_scatter}`.
   That is how the analysis tooling knows a figure is already placed; break it and
   re-running a notebook appends a duplicate block.

4. **Do not hand-edit `tables.tex`.** It is generated. Edits are overwritten on the next
   save. Change the notebook that produced it.

5. **Do not commit the built PDF.** It is stale by definition and conflicts on every push.

6. **Never describe a figure you have not looked at.** A caption plus a confident
   description is a fabricated result with a real label attached. If asked about a figure,
   read the actual image file.

## Layout

| Path | What it is |
|---|---|
| `main.tex` | Root: document class, then one `\subfile` per section in reading order |
| `document_settings.sty` | Packages, `\graphicspath`, bespoke macros |
| `glossary_terms.tex` | Acronyms and glossary entries (optional) |
| `Preamble/` | Title page, abstract, acknowledgements, contents |
| `Sections/<Name>/` | One directory per section: its `.tex`, `Figures/`, `tables.tex` |
| `Bibliographies/` | `.bib` sources |
| `.doc-publish/` | Publishing state and the document's answering rules. Data, not markup. |

`\chapter` is a `report`/`book` class command and is used normally. The *directory* is
`Sections/` because the tooling is document-agnostic; the two are unrelated.

## Commands

```bash
make                  # build the PDF locally (Overleaf runs its own toolchain)
make clean

# only if the publishing engine is installed:
doc-publish doctor    # what is set up and what is not — start here
doc-publish build     # LaTeX -> corpus; non-zero on anything unresolved
doc-publish check     # is this document ready to publish?
```

`doc-publish doctor --json` gives the same findings as a machine-readable object. If you
are helping someone set this up, run that and work from it rather than guessing.

## Helping someone set this up

The end-to-end guide is [SETUP.md](SETUP.md). The short version:

1. `doc-publish doctor` — read what is missing.
2. Fix what it reports, in the order it reports it.
3. `doc-publish build` — must exit 0.
4. `doc-publish check` — gates publishing; fails until `.doc-publish/prompt.md` is written.

**A build failure is a failure, not a warning.** `doc-publish build` exits non-zero on an
unresolved macro, a missing figure asset, or an ambiguous filename. Nothing is dropped
silently — unresolvable things become `[UNRESOLVED: ...]` markers. Do not suppress them or
edit them out of the corpus; fix the cause. The silent version reads plausibly: an
unexpanded count macro turns "a family of `\nmodels{}` variants" into "a family of
variants" and the number is simply gone.

## When asked about the document's content

If `.doc-publish/prompt.md` exists, **read it first.** It holds this document's own
answering rules — what its comparisons do and do not establish, which numbers are
contested. Those rules cannot be inferred from the text.

Then answer from `build/corpus_draft.md` (or `corpus_public.md`), not by reading the
`.tex` files. Cite sections as §N.N. Separate what the document **demonstrates** from what
it **argues** from what is **your extrapolation** — never let the third borrow the first's
authority. If you cannot locate a claim, say so rather than reconstructing it from general
knowledge.

Lines marked `> [draft note]` are LaTeX source comments: drafting state, not findings.
Never present one as a result.

## Two corpora, and only one may leave the machine

`corpus_public.md` has source comments stripped and is safe to share.
`corpus_draft.md` keeps them — provenance, TODOs, contested numbers, supervisor questions
— and is **for the author only**. Never paste draft-corpus content into anything outbound.
`build/` and `data/` stay gitignored.
