# writing-template

A long LaTeX document — thesis, report, book — laid out so that **the prose is the only
thing you write by hand**. Figures and tables are generated by a companion analysis
repository and land here as artefacts; a publishing agent can flatten the result into a
wiki or a site; Overleaf compiles it unchanged.

```
  analysis repo ──> figure ──┬─> PNG committed here ──> Overleaf ──> the PDF
                             └─> interactive HTML ────> wiki / site
```

The point of the split is that one figure object produces both outputs, so the PDF and
the published version can never disagree.

## Start here

This is a **GitHub template**, not a repository to fork or clone: the copy you write in
is your own repository, with its own history and no link back here.

**1. Create your repository.** On
[c-energie/writing-template](https://github.com/c-energie/writing-template), press
**Use this template → Create a new repository**. Name it after your document, and make it
private if the work is unpublished — a template's visibility is not inherited.

**2. Clone it and fill in the placeholders.**

```bash
git clone https://github.com/<you>/<your-document>.git
cd <your-document>
python init.py          # asks for title and author, rewrites them, deletes itself
```

`init.py` exists because "Use this template" copies files verbatim — it cannot substitute
a title. Run it once, in **your** repository; it edits in place and then removes itself,
so it is not something to run in a checkout of the template.

To run it unattended, pass the answers as flags instead: `python init.py --title "…"
--author "…"`. A flag skips its question. With no terminal to ask on, a left-out
`--title` becomes "My Document" and a left-out `--author` stops the script.

**3. Prove it builds.** `make` locally, or push to Overleaf ([below](#overleaf)). Nothing
else has to work yet.

**4. Make it your document.** Replace `Sections/Example/` with a section of your own,
then in two places:

- `main.tex` — one `\subfile` line per section, in reading order.
- `document_settings.sty` — one `\graphicspath` line per directory that holds figures.
  It does **not** recurse, and a missing line is the usual first build failure.
  Beside it, one `\InputIfFileExists{Sections/<Name>/values.tex}{}{}` line per section
  that has computed values — see [below](#four-conventions-the-tooling-depends-on).

**5. Commit and push.** Everything past this point is optional and additive — Overleaf,
the analysis repository and publishing can each be added months later, in any order.

You need a LaTeX toolchain only for step 3; Overleaf builds without one. `init.py` is
stdlib Python 3, no install.

**Setting up the whole toolchain, or adapting a document you already have?** See
[SETUP.md](SETUP.md) — the order the three repositories go together, what an existing
thesis actually has to satisfy, both Overleaf workflows, and a troubleshooting table.

Working with an AI assistant? [AGENTS.md](AGENTS.md) is read by Cursor, Copilot, Codex,
Claude Code and the rest; [docs/setup-prompt.md](docs/setup-prompt.md) is a prompt to
paste into any chat assistant that has no access to your files.

## Layout

| Path | What it is |
|---|---|
| `main.tex` | Document root: class, then one `\subfile` per section in reading order |
| `document_settings.sty` | Packages, `\graphicspath`, bespoke macros |
| `glossary_terms.tex` | Acronyms and glossary entries, all in one place |
| `Preamble/` | Title page, abstract, acknowledgements, contents |
| `Sections/<Name>/` | One directory per section: its `.tex`, its `Figures/`, its `tables.tex` and `values.tex` |
| `Bibliographies/` | `.bib` sources |
| `setup-nested.sh` | Sets up the nested layout, below; `tests/` holds its test |
| `layout.toml` | Written by `setup-nested.sh`; absent until you choose the nested layout |

Sections use `\subfile`, so each one compiles on its own while you draft it.

## Four conventions the tooling depends on

**Figures are referenced by bare filename.** `\includegraphics{example_scatter.png}`,
never a path. `\graphicspath` in `document_settings.sty` resolves it, and the analysis
repo writes figures by name. It **does not recurse** — every directory holding figures
needs its own line, and one that is missing produces a build error with no hint why.

**Computed numbers are loaded per section.** The analysis repo's `save_value` writes
each number it computes as a macro into `Sections/<Name>/values.tex`, so the prose says
`\exampleValue` rather than a value copied out of a notebook. The document only sees it
if `document_settings.sty` has one `\InputIfFileExists{Sections/<Name>/values.tex}{}{}`
line for that section, next to `\graphicspath` — hand-added, like the figure
directories, and `save_value` warns when it is missing. The file is loaded once, in
the preamble, so its macros work in any section; a missing file is not an error, but
a macro used without its file is. **Never edit `values.tex` by hand** — it is
regenerated on the next save.

**Labels mirror filenames.** A figure saved as `example_scatter.png` is labelled
`\label{Fig: example_scatter}`. That is how the analysis tooling knows this figure is
already referenced here, and therefore that re-running the notebook must not append a
second block. Rename one without the other and you get duplicates.

**Never rename a committed figure.** The bare-filename convention means a rename breaks
`\includegraphics` and any agent indexing by name, both silently.

## The LaTeX class

`main.tex` uses the standard `report` class so this template builds anywhere. Most
institutional classes are redistributed under their own terms, so none is shipped: drop
the `.cls` beside `main.tex` and swap the `\documentclass` line.

```latex
\documentclass[12pt,phd,a4paper,oneside]{ucl_thesis}
```

Writing a paper on `article` or a journal class works too. The abstract,
acknowledgements, contents and lists adapt to a class without chapters. The rest
needs a few edits by hand, listed in
[Writing a paper](SETUP.md#writing-a-paper-article-or-a-journal-class).

## Overleaf

Overleaf's git bridge expects a repository whose root holds the document. This layout
satisfies that as-is:

```bash
git remote add overleaf https://git.overleaf.com/<project-id>
git push overleaf main
```

Two things to know. Overleaf runs its own toolchain, so the `Makefile` is for local
builds only — anything the document actually needs belongs in `main.tex` or
`document_settings.sty`. And `.doc-publish/` is data, not markup: Overleaf ignores it and
the document builds identically without it.

## Publishing beyond Overleaf

To turn this document into a queryable corpus, a wiki or a static site,
[`doc-publish`](https://github.com/c-energie/doc-publish) scaffolds what it needs:

```bash
pip install doc-publish
export DOC_REPO=$PWD
doc-publish init      # writes .doc-publish/ and two authoring skills
doc-publish check     # reports what is still unfinished
```

That directory is **data, not markup** — Overleaf ignores it and the document builds
identically without it. It is not shipped in this template on purpose: the engine owns the
shape of its own contract, so scaffolding it from the engine means a template can never
hand you a stale copy.

`init` also writes two Claude skills into `.claude/skills/`, for the two files that are
real work: the prompt that stops an agent misrepresenting your findings, and the adapter
that teaches it your bespoke macros.

## The companion analysis repository

Figures and tables come from
[`analysis-template`](https://github.com/c-energie/analysis-template). It takes this
repository as a build input through the `DOC_REPO` environment variable and writes
into `Sections/<section>/Figures/`. It never reads your prose; this repository never
imports its code. That is deliberate — either half is usable alone.

## The analysis repo inside this one

The analysis repo can also live inside this repo, as a **nested repo** in a gitignored
subdirectory, so one directory holds the whole package. Choose it when the document and
its analysis go together. Keep them side by side if one analysis repo feeds several
documents.

```bash
sh setup-nested.sh                       # create one from analysis-template (needs gh)
sh setup-nested.sh --from <url-or-path>  # or adopt an existing one; also how to move an
                                         # existing pair into this layout
```

It records the layout in `layout.toml`. Commit `layout.toml` and `.gitignore` here, and
commit everything inside the nested directory from inside it, in its own repo. On a fresh
clone, `sh setup-nested.sh` with no arguments restores the nested repo from `layout.toml`.
The script never writes `DOC_REPO`. Until the analysis repo reads it from `layout.toml`, set
it in the nested repo's `.env`. Overleaf only sees tracked files, so the nested directory
never reaches it; the script and `layout.toml` sync there and do nothing. On Windows, run
it in Git Bash. The details are in
[SETUP.md](SETUP.md#the-nested-layout-the-analysis-repo-inside-this-one).

## What is not here

No CI, no publishing workflow, no `.pdf`. A built PDF in version control is stale by
definition and conflicts on every push; Overleaf builds its own.
